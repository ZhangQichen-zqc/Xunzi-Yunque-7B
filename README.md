# Xunzi-Yunque-7B（荀子·云阙）

**面向复杂格律对齐的宋词生成大模型**  
*Xunzi-Yunque: A Large Language Model for Song Ci Generation with Complex Prosodic Alignment*

> **模型权重（ModelScope）：** [Fanezonw/Xunzi-Yunque-7B](https://modelscope.cn/models/Fanezonw/Xunzi-Yunque-7B)  
> **项目仓库（GitHub）：** [ZhangQichen-zqc/Xunzi-Yunque-7B](https://github.com/ZhangQichen-zqc/Xunzi-Yunque-7B)  
> **基础模型：** [Qwen2.5-7B-Instruct](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct)  
> **研究单位：** 南京农业大学信息管理学院

## 简介

**Xunzi-Yunque** 是一个基于 Qwen2.5-7B-Instruct 构建、面向宋词复杂格律对齐的古典诗词生成模型。模型致力于解决通用大语言模型在宋词创作中普遍面临的“重语义、轻格律”问题：既要遵守词牌规定的字数、句读、平仄和押韵规则，也要尽可能保留宋词应有的意境、连贯性与文学表达。

不同于句式相对规整的近体诗，宋词具有长短句交错、词牌变体丰富、平仄约束复杂等特征。为此，本研究从《钦定词谱》《词林正韵》等传统词学文献出发，构建结构化格律知识库，设计多维量化评价算法 **SongCiReward**，并采用 **冷启动监督微调（SFT）—思维链监督微调（CoT-SFT）—组相对策略优化（GRPO）** 的三阶段递进式训练策略，逐步增强模型对宋词形式约束与表达要求的适应能力。

在本研究设置的宋词格律评测中，Xunzi-Yunque 的综合得分达到 **80.86**，相较基础模型的 **37.43** 有明显提升，并接近真实宋词基准的 **83.46**。在双盲人工评价中，模型生成词作的评分有 **76.82%** 落在 4—5 分区间，体现出较好的主观文学表现。

## 主要特点

- **轻量化的领域对齐：** 基于 7B 参数量级的 Qwen2.5-7B-Instruct，通过多阶段后训练提升宋词生成能力，减少对超大参数模型的依赖。
- **复杂格律精细约束：** 结合词牌变体、字数、句读、平仄与韵脚规则，针对宋词长短句及复杂声律开展定向优化。
- **知识驱动的规则建模：** 对《钦定词谱》《词林正韵》进行结构化处理，建立词牌规则库与汉字声律数据库，为训练数据构建与客观评测提供支持。
- **多阶段递进式训练：** 依次使用高质量宋词数据进行冷启动 SFT、使用蒸馏推理数据进行 CoT-SFT，再通过 GRPO 强化格律遵循能力。
- **多维奖励与防作弊机制：** 使用 SongCiReward 评价平仄和韵脚表现，并对句读结构不符、过度复述参考词作等行为施加惩罚。
- **兼顾形式与文学表达：** 在客观格律评分之外，进一步通过双盲人工评价考察作品的连贯性、意境及文学表现。

## 使用方法

### 1. 环境准备

建议在支持 PyTorch 的 GPU 环境中运行。以下为基础推理依赖，实际使用时请结合已发布权重、CUDA 环境和依赖版本进行测试：

```bash
pip install torch transformers accelerate modelscope
```

> **发布说明：** ModelScope 已上传完整分片权重（非仅 LoRA Adapter）。以下为通用 Transformers 加载示例，仍须在有足够算力的环境中验证。

### 2. 模型加载（ModelScope）

```python
from modelscope import snapshot_download
from transformers import AutoModelForCausalLM, AutoTokenizer

# 已上传的模型仓库（仓库设为公开后可供其他人访问）
model_id = "Fanezonw/Xunzi-Yunque-7B"
model_dir = snapshot_download(model_id)

tokenizer = AutoTokenizer.from_pretrained(model_dir, trust_remote_code=True)
model = AutoModelForCausalLM.from_pretrained(
    model_dir,
    torch_dtype="auto",
    device_map="auto",
    trust_remote_code=True,
).eval()
```

### 3. 宋词生成示例

下面以《卜算子》为例。模型训练过程中使用了包含词牌、格律、参考词作及输出格式等要素的结构化提示词；实际应用时，建议提供充分且准确的词牌规则信息，以提高输出一致性。

```python
query = """请作为一位宋代词人，按照以下要求创作一首宋词：
1. 词牌名：卜算子
2. 创作主题：咏日
3. 押韵要求：遵循《词林正韵》
4. 格律要求：遵循《卜算子》对应词牌变体的字数、平仄和句读规则
5. 输出格式：采用宋词上下阕结构；将创作思路写在 <reasoning> 标签中，
   最终词作写在 <answer> 标签中。"""

messages = [{"role": "user", "content": query}]
text = tokenizer.apply_chat_template(
    messages, tokenize=False, add_generation_prompt=True
)
inputs = tokenizer(text, return_tensors="pt").to(model.device)

outputs = model.generate(
    **inputs,
    max_new_tokens=512,
    do_sample=True,
    temperature=0.7,
    top_p=0.9,
)

new_tokens = outputs[0][inputs["input_ids"].shape[-1]:]
print(tokenizer.decode(new_tokens, skip_special_tokens=True))
```

**论文中的实际生成案例**（《卜算子》，主题“咏日”）：

> 欲上云霄路，先下泥涂处。  
> 一点光华万丈长，照破昏衢曙。  
>  
> 欲去还须住，欲住还须去。  
> 去住由他各自由，明晦非君主。

该词作为论文中的案例输出，**并非上面示例代码每次运行都会产生的固定结果**。论文报告该案例的 SongCiReward 综合得分为 **99.09**。

### 4. 格律要求说明

Xunzi-Yunque 面向宋词创作任务，主要考虑下列约束：

| 约束维度 | 说明 |
| --- | --- |
| 词牌 | 研究选取 30 个高频词牌，涵盖小令、中调与长调 |
| 变体 | 评测中整理了 192 种不同的词牌变体规则 |
| 字数与句读 | 按所选词牌变体控制总字数、句式和断句结构 |
| 平仄 | 依据结构化词谱与汉字声律数据库检查对应字位 |
| 押韵 | 依据《词林正韵》的韵部信息检查韵脚一致性 |
| 主题意象 | 可在提示词中指定主题、意象及创作语境 |

**注意：** 上述内容描述研究覆盖范围及训练、评测所使用的规则，并不意味着模型对全部词牌及变体都能保证百分之百的合律输出。对格律要求严格的应用，建议结合 SongCiReward 或人工词学校验进行复核。

## 技术细节

### 1. 结构化词学知识库

研究以《钦定词谱》和《词林正韵》为核心知识来源，重构词牌变体、平仄序列、韵脚位置、句读边界等规则，并建立汉字声调与韵部映射。研究中还整理《全宋词》相关语料，为监督微调、评测与人工对照提供素材。

### 2. SongCiReward 多维格律评价机制

SongCiReward 接收待评词作、词牌规则库及声律数据库，筛选字数相符的候选词牌变体，对**全词平仄**与**韵脚一致性**进行量化评价。论文中采用平仄与押韵约 **4:6** 的组合权重，并对句读结构不匹配等情况进行惩罚；最终取各候选变体中的最高得分作为该词作的量化评价结果。

该机制同时用于训练数据筛选、GRPO 奖励反馈以及最终模型评估。具体实现请以团队正式公开的 `SongCiReward` 源代码为准。

### 3. 三阶段递进式对齐

| 阶段 | 训练方法 | 目标 |
| --- | --- | --- |
| Stage 1 | 冷启动 SFT | 使用高质量指令语料，建立对宋词基本体式的遵循能力 |
| Stage 2 | CoT-SFT | 通过推理数据学习意境组织、平仄推演与韵部选择 |
| Stage 3 | GRPO | 利用 SongCiReward 反馈进一步降低出律风险 |

在冷启动阶段，研究从语料池中筛选出 **500** 条高质量数据，其中包括 **413** 条人类经典词作及 **87** 条高分模型生成语料；思维链阶段采用 DeepSeek-R1-671B 蒸馏生成的推理数据，并结合人类词作数据进行训练。最终选择 **GRPO 第 700 步**的权重开展后续评测。

## 评估结果

### 1. 多模型格律客观评测

研究使用统一的结构化提示词与 SongCiReward 进行客观评价。以下为论文报告的结果，分数为对应测试设置下的量化指标：

| 模型 | 平仄得分 | 韵脚得分 | 综合得分 |
| --- | ---: | ---: | ---: |
| Qwen2.5-7B-Instruct | 40.73 | 35.22 | 37.43 |
| Qwen2.5-7B-Instruct-SFT | 61.42 | 52.84 | 56.27 |
| Qwen2.5-7B-Instruct-SFT-CoT | 80.53 | 71.00 | 74.81 |
| **Xunzi-Yunque（Ours）** | **88.00** | **76.11** | **80.86** |
| DeepSeek-R1-671B | 50.45 | 47.23 | 48.52 |
| Xunzi-Yayun-R1-32B | 22.26 | 20.85 | 21.41 |
| 真实宋词基准 | 86.87 | 81.18 | 83.46 |

这些数字反映**宋词任务、给定提示词及特定评价机制下**的表现，不宜直接解释为模型在所有古典文学任务上的通用能力排名。

### 2. 双盲人工评价

研究邀请 **10 位**具有古典文学基础的本科生参与评分，使用 1—5 分李克特量表，评价生成作品的文学表现与人类创作相似程度。

- **76.82%** 的评分位于 **4—5 分**（“疑似是人类”或“非常确定是人类”）。
- **9.11%** 的评分位于 **1—2 分**（偏向机器创作判断）。

这一结果反映了本研究人工评价样本中的主观判别分布，并不代表模型输出有 76.82% 的概率必定能通过任意图灵测试。

## 应用场景

- **古典诗词创作辅助：** 根据指定词牌、主题和意象生成宋词初稿。
- **数字人文与计算文学：** 探索传统文学知识的结构化、量化评价与生成式利用。
- **古典文学教学：** 辅助理解词牌变体、平仄和押韵约束；输出仍需教学者复核。
- **古籍知识资源开发：** 为格律规则库、古典文学智能工具和相关研究提供方法参考。
- **人机协同创作：** 支持研究者或创作者在机器初稿基础上开展人工校订与再创作。

## 局限性

- 受 7B 参数规模及训练数据范围影响，模型对生僻意象、历史典故及复杂长调的处理仍有局限。
- SongCiReward 侧重可计算的形式约束，难以完整刻画文学情感、审美价值和艺术原创性。
- 格律得分属于特定规则库与评测流程下的实验指标，实际输出仍可能出现出律、用韵不当或语义生硬的问题。
